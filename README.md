# Kuda Poyti Bot — «Куда пойти»

Минимальный русскоязычный Telegram inline-бот @Kuda_PoytiBot для поиска мест в России и отправки стандартных карточек Venue с картой, адресом и координатами. Личное использование с очень небольшой нагрузкой. Node.js 24 LTS, TypeScript, grammY, нативный fetch, Nominatim / OpenStreetMap. Без БД, webhook, домена и входящих портов.

## Подготовка Telegram

В @BotFather включите `/setinline` для бота, например с подсказкой `Название, город и !`. Токен получите через BotFather и храните только в `.env` на своём компьютере/сервере. В GitHub его добавлять нельзя.

## Локальный запуск

```sh
npm ci
cp .env.example .env
# заполните .env в редакторе
npm run build
node --env-file=.env dist/index.js
```

Для разработки: `npm run dev`. Проверки: `npm test` и `npm run build`.

| Переменная | Значение |
| --- | --- |
| BOT_TOKEN | Обязательный токен Telegram |
| NOMINATIM_CONTACT_EMAIL | Обязательный действующий контакт разработчика; передаётся Nominatim в User-Agent |
| NOMINATIM_URL | Базовый URL совместимого сервера, по умолчанию https://nominatim.openstreetmap.org |
| LOG_LEVEL | debug, info, warn, error, silent; по умолчанию info |

Запуск через `npm start` предполагает, что переменные уже экспортированы в окружение. `.env` автоматически читается командами выше и Docker Compose. Значения конфигурации проверяются перед подключением к Telegram. Логи намеренно краткие, без токенов, поисковых строк и идентификаторов пользователей.

## Использование

Откройте любой чат, введите запрос и дождитесь результатов:

```text
@Kuda_PoytiBot Эрмитаж Санкт-Петербург !
@Kuda_PoytiBot Пятёрочка Воронеж !
@Kuda_PoytiBot Магнит Москва !
@Kuda_PoytiBot Красная площадь Москва !
```

Выберите место, чтобы отправить карточку в текущий чат. `/start` показывает инструкцию. Для редактирования запроса сначала удалите `!`, завершите ввод и снова поставьте `!` в конце. Без завершающего символа внешних запросов нет. Длина текста поиска — 2–200 символов, управляющие символы и внутренние `!` запрещены. При пустом ответе или ошибке кнопка переводит в личный чат с пояснением.

## Nominatim: обязательные ограничения

Перед использованием прочитайте [политику публичного Nominatim](https://operations.osmfoundation.org/policies/nominatim/). Публичный сервер имеет ограниченные ресурсы, может отказать в доступе и не гарантирует доступность. Ответственность за соблюдение политики несёт разработчик/оператор приложения. Этот проект предназначен для осознанно выбранного личного сценария, не для перепродажи API или массового геокодирования.

- Запрос только по явному завершению `!`; автодополнения, фоновых поисков и автоматических повторов нет.
- Максимум один старт внешнего запроса в секунду на процесс, максимум один активный запрос. При занятости новый отличный запрос отклоняется сразу, очередь отсутствует.
- **Запускайте только один экземпляр приложения**: не масштабируйте Compose, не запускайте одновременно локально и на VPS с тем же публичным сервисом. Лимит относится ко всему приложению, а не каждому пользователю.
- User-Agent: `KudaPoytiBot/1.0 (контактный email)`.
- Кэш до 100 запросов: успешные результаты на 24 часа, пустые на 10 минут; одновременные одинаковые поиски объединяются. Кэш теряется при перезапуске.
- Таймаут fetch — 6 секунд, включая чтение ответа. Для 429/5xx действует пауза Retry-After либо 30 секунд; ошибки не кэшируются.
- Общий запрос не отменяется при изменении ввода одним пользователем: результат может ожидать другой пользователь. Telegram получает ответ для исходного inline_query; бесконечных ожиданий нет благодаря таймауту.
- Нельзя использовать для сбора всех организаций района, массовых/систематических выгрузок. Не вводите персональные или конфиденциальные данные: текст завершённого поиска передаётся внешнему провайдеру.
- Сервер можно сменить через NOMINATIM_URL без изменения кода. Адаптер `PlacesProvider` позволяет заменить поисковую реализацию.

Каждый запрос содержит `countrycodes=ru`, `accept-language=ru`, `addressdetails=1`, `limit=40`. Ответы с присутствующим кодом страны, отличным от `ru`, отбрасываются. Невалидные координаты и дубликаты исключаются. Если название отсутствует, используется исходный display_name; названия организаций не выдумываются. При отсутствии адреса используется исходное название.

Nominatim — геокодер, а не полный каталог заведений. Поиск категорий через него не выполняется. Первый результат не обязательно самый релевантный. Покрытие, актуальность, границы и доступность мест определяются данными провайдера. Живой поиск требует реального токена и контакта; автоматические тесты никогда не обращаются к публичному API.

## Docker

Установите Docker Engine и Compose v2, заполните `.env`:

```sh
docker compose config --quiet
docker compose build
docker compose up -d
docker compose logs --tail=50 bot
# остановка
docker compose down
```

Compose автоматически подставляет переменные из `.env`, проверяет обязательные значения, перезапускает контейнер при сбое. Порты и volumes не нужны. Образ собирается в два этапа, работает от пользователя node с файловой системой только для чтения. SIGTERM/SIGINT останавливают long polling, Compose даёт 15 секунд на завершение, fetch ограничен 6 секундами.

## Структура

- `src/bot.ts`: Telegram /start и inline_query, карточки Venue.
- `src/services/places.ts`: проверка ввода, кэш и объединение запросов.
- `src/providers/nominatim.ts`: HTTP, параметры, преобразование в независимую модель Place.
- `src/utils/`: ограничитель частоты и ограниченный кэш.
- `src/config.ts`, `src/index.ts`: настройки, запуск и остановка.
- `tests/places.test.ts`: мокированные HTTP-ответы, разбор запросов, Россия, преобразование, пустые результаты, rate limit, ошибки и кэш.

## Подготовка VPS

Нужны Docker Engine / Compose v2, исходящие HTTPS-соединения к Telegram и выбранному Nominatim, действующий токен, контактный email и включённый inline mode. Скопируйте исходники, создайте `.env` с правами `600`, выполните Docker-команды выше. SSH-пароли не сохраняйте в репозитории. Не открывайте входящие порты для этого бота. На текущем этапе развёртывание не выполняется.

## Текущий MVP и будущее подключение категорий

Поиск названий (включая сети) работает через Nominatim с явным `!`.
Категории `кафе`, `рестораны`, `супермаркеты`, `продуктовые магазины` распознаются,
но публичный Overpass не прошёл проверку (HTTP 406), поэтому в production отключён.
`Магазины` — неподдерживаемая широкая категория; вместо неё введите конкретное название. Ошибка отображается кнопкой перехода в личный чат,
а не фиктивной карточкой. Реальные заведения из моков не показываются.

Реализованы экспериментальные CityResolver/Overpass и пагинация сохранённой выборки по 10 Venue.
Они проверены на моках; полный охват организаций города не обещается.
Подробности, измерения, схема и условия включения: [исследование](docs/hybrid-search-research.md).

Overpass-адаптер и CityResolver сохранены только как экспериментальный код и не подключаются в `src/index.ts`. Переменных `OVERPASS_ENABLED` и endpoint в конфигурации нет: установка произвольной переменной не включает адаптер. Запуск не требует доступа к Overpass. `HybridPlacesProvider` принимает необязательный `CategoryPlacesProvider`, который в будущем сможет объединить разрешение города и любой источник; Telegram работает только с общим `Place`.

Nominatim запрашивается один раз с лимитом 40 объектов. Сохранённая выборка выдаётся по 10 карточек через `offset`/`next_offset`, без дополнительных HTTP-запросов между страницами. Последняя страница не содержит продолжения. Сессии живут 5 минут, до 50 записей и 4 МБ; некорректный или истёкший offset предлагает повторить поиск с `!`. Это пагинация ограниченной выборки, а не всех организаций или всех возможных результатов Nominatim. Будущий источник может реализовать продолжение в сервисе `Places.page`, сохранив контракт Telegram-обработчика.

Кафе, рестораны, супермаркеты и продуктовые магазины распознаются, но возвращают «Поиск категорий временно недоступен» без сетевых запросов. Для проверки текущего MVP используйте конкретные названия из примеров выше.
